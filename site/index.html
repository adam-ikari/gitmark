筆記就是 git 倉庫裡的
markdown 檔

儲存是一次 commit。推送與拉取是同步。兩個人同時改到同一段時， 三方合併會自動處理；真的合不起來才會停下來找你。 沒有私有雲、沒有資料格式轉換 —— 筆記離開這個 app 仍然是可讀的純文字。

01三個主張

git 就是儲存層，不是附件

沒有資料庫。整份筆記倉庫是一個 git repo，透過 isomorphic-git 在裝置上直接操作。歷史是免費的， 而且你隨時可以離開這個 app 用任何工具改同一份檔案。

安全優先於自動

改動不重疊就自動合併；重疊且無法化解才升級為衝突，而且 整個同步會停下來，不 commit、不推送。 把帶衝突標記的 commit 推上去，等於把一個人的未解問題變成所有人的問題。

markdown 是唯一真實來源

編輯器是 markdown 的一個視圖。每次操作都是對原文的 最小文字替換，不是重新序列化。 選取「italic」按粗體，只會在那八個字元周圍插入 **， 其餘部分保持 byte-identical —— 否則 git log 會被雜訊淹沒。

02功能

Markdown 渲染

標題、清單、任務清單、引用、表格、巢狀清單、GFM 刪除線。行內樣式以淡化標記顯示，段落結構為真實排版。

Mermaid 圖

```mermaid 圍欄直接渲染流程圖、時序圖、類別圖。沙盒化的 WebView，版本釘死以免大版本更新靜默改變每一張圖。

SVG

```svg 圍欄以 react-native-svg 原生向量渲染，任何縮放下都保持銳利。看不懂的元素會明確回報，不會靜默消失。

原生富文本編輯

每個段落一個原生輸入元件。粗體、斜體、行內程式碼、刪除線、標題層級、清單縮排、任務勾選，全部可用。

Frontmatter metadata

檔案內建 --- 區塊承載標題、標籤、建立與更新時間。解析器會回報精確的位元組範圍，所以改動內文不會重寫中繼資料。

衝突標記

真的衝突用標準 diff3 標記寫進檔案，任何工具開啟都看得見。狀態列確保你不會在幾週後才發現它還沒解決。

03架構

分層的唯一規則：core/ 是純 TypeScript，不 import 任何 React Native 或 Node API。所有副作用都在邊緣被注入。

core/

可直接在 Node 測試
  • markdown — inline 與 block 解析、樣式片段
  • merge — LCS diff、hunk 群聚、diff3 三方合併
  • richtext — 文字 splice、行內與區塊編輯操作
  • note — frontmatter 解析與序列化
  • svg — XML 讀取器與形狀樹
  • git — 可注入的檔案系統與傳輸介面

app/

React Native
  • components — 區塊編輯器、渲染器、狀態列
  • git — fetch 傳輸、isomorphic-git 轉接層
  • screens — 編輯、渲染、筆記列表
  • theme — 設計代幣

這個邊界不是潔癖：正是因為 core/ 能在無模擬器、無網路的 環境下測試，三方合併與編輯操作才可能有 347 個測試。而它與 isomorphic-git 的差異化測試顯示， 合併決策與參考實作在 27 個案例中全部一致，只有一個刻意的政策差異。

04現況與驗證邊界

已完成並驗證

  • 347 個單元測試全數通過，涵蓋合併、編輯、解析、frontmatter
  • Android bundle 成功建置（713 個模組）
  • isomorphic-git 對真實 GitHub 驗證通過 clone / listFiles / log
  • diff3 與 isomorphic-git 內建的參考實作做差異測試

尚未在實機驗證

  • 編輯器兩層的字型度量對齊（需實機或模擬器）
  • 中文輸入法（IME）組字期間的行為
  • 真實 GitHub 上的 push 與權限流程
  • mermaid 與 SVG 在裝置上的實際顯示

一個被推翻的設計。 最初的方案是「底層渲染富文本 + 上層蓋一個透明輸入框」。 實測 react-native@0.86.3 原始碼後確認它行不通： Android 的 TextInput 不接受 styled children， 而隱藏的 markdown 標記不會移除它的 advance width —— 兩層字元流不同，軟換行必然錯位。 這不是調校問題，是架構矛盾。 現有方案改成每個段落一個原生輸入框，兩層持有相同的字元， 因此可以對齊。
